The idea

One edition a day, like a paper on the doorstep. The news is fetched at 04:30, the edition is printed at 05:00, and once it is printed it never changes.

Each edition has a number, Br., which counts days since the first print. Verzija counts reprints of the same day: if something has to be fixed after 05:00, a new version is printed beside the old one, and the old one stays readable in the archive. Nothing is edited in place.

Every edition is a single index.html that stands on its own. It can be saved, mailed or opened from a disk in ten years and it will look and work the same, because it does not call back to any server. The archive is just a folder of these files.

The program behind it is one Go binary with Postgres. It fetches, prints and serves the site, and it has a small dashboard (htmx) where the admin writes the main article, manages categories and their sources, and checks the fetchers. There is one user, the admin.

Running it

Today: the static design Stage 0

The design folder is plain HTML, CSS and a little JavaScript. Serve it over HTTP rather than opening it from disk, because browsers block some features on file:// (the weather icons are CSS masks, and the game fetches its word list).

cd tisak2/design
python3 -m http.server 8000
# open http://localhost:8000/ and http://localhost:8000/docs.html

The program Stage 1

It needs Go 1.24 and Postgres 16. Create a role and a database once:

sudo -u postgres psql -c "CREATE ROLE tisak LOGIN PASSWORD 'tisak'"
sudo -u postgres psql -c "CREATE DATABASE tisak OWNER tisak"

Then build and run it from the tisak2 folder:

go build -o tisak ./cmd/tisak
./tisak -migrate                    # create the tables and the first categories and sources
./tisak -check                      # try the database and every source, saving nothing
./tisak -fetch-now                  # run every fetcher once and show a report
./tisak -print-now                  # print today's edition (fetches first if the last fetch is old)
./tisak -print-now -reason "ispravak"   # a reprint: Verzija 2, with its reason in the archive
./tisak                             # serve the site, with the 04:30 fetch and 05:00 print built in

Settings come from flags or the environment. Keys for TMDB and NASA will come from the environment too, from Stage 3 on; they never go in a file.

FlagEnvironmentDefault
-dbDATABASE_URLpostgres://tisak:tisak@localhost:5432/tisak
-dataTISAK_DATAdata: holds media/ (the picture store) and editions/
-addrTISAK_ADDR:8080
-siteTISAK_SITE/: the site's root, for the archive link printed in each edition
-fetch-at, -print-at04:30, 05:00, Zagreb time
-devoff; when on, templates and styles are read from ./web on every print, so edits show without a rebuild

If the program starts after 05:00 and today has no edition yet, it fetches and prints straight away, so a restart or a late deploy never skips a day.

The code Stage 1

One module, tisak, with a package for each job. Each one is small enough to read in one sitting.

PackageJob
cmd/tisakThe binary: flags, the daily loop, and seed.go with the first categories and sources.
internal/storePostgres. Migrations are numbered SQL files built into the binary; tables are media, categories, sources, items and editions.
internal/fetchFetchers, one per kind (rss, hn), and the runner that calls them four at a time with a 60 second limit each and records how each one did.
internal/mediaThe picture store: download, shrink, name by hash.
internal/pressPicks the cards, freezes them into a snapshot, renders the templates and writes the edition folder.
internal/siteServes finished editions from disk and the archive page. It never renders news itself.
web/templates, web/staticThe page, cut from this design, plus the CSS, fonts, icons and scripts. All built into the binary.

How a print picks cards

  • Each category has a layout, which sets how many cards it holds: row3 3, rows3 6, lead2 3, lead2row3 6, list 12, six 12 (Hacker News).
  • Each source has a share per edition. The press takes the newest items from the last 36 hours, a few from each source in turn, until the layout is full, and skips a story another source already carried.
  • In a category with a lead picture, the first card that has one goes to the lead spot.
  • Sve iz dana lists everything fetched in the last 24 hours, by category and source.
  • What was picked is stored with the edition as JSON, so any edition can be inspected or rendered again later.

Reader settings

The gear in the footer opens a small panel. Each choice is an attribute on <html> and is remembered in the reader's browser. A tiny script in <head> sets the attributes before the page paints, so there is no flash of the wrong theme.

SettingAttributeValues (first is default)Stored as
Typedata-typesans (Geist), serif (Spectral)type
Lookdata-modedigital, print (newspaper: page frame, double rules)mode
Coloursdata-themelight (no attribute), dark, sepia (the dark theme in browns)theme
City#city selectZagreb, Split, Rijeka, Osijek, Zadar, Pula, Dubrovnik, Varaždin. Every city's forecast is printed into the page as a .weather-day[data-city] block; the picker only chooses which one shows.city

Every read and write of localStorage is wrapped in try, so a private window or blocked storage only means the page forgets the choice; it never breaks.

Design tokens

Colours live in section 2 of index.css, type in section 3, and the look (digital or newspaper) in section 4. Components use only the tokens, so a theme is a short list of values.

Type

--ff-sans is Geist and --ff-serif is Spectral. --font-head and --font-body switch with data-type; --font-ui (labels, tabs, dates) stays Geist in both, so small text stays crisp. Weights come from --w-head, --w-sub and friends.

Look

--col-rule, --rule-light, --section-rule and --panel-top are thin single lines in the digital look and become double and heavier rules in the newspaper look. Components never draw their own borders from raw colours.

Components and hooks

Behaviour hangs off data- attributes, so the press only has to print the right markup.

Tabs: data-tabs

Any element with data-tabs becomes a tab box. Buttons carry data-tab="key"; the panel with the matching data-panel="key" is shown and the rest get hidden. Arrow keys move between tabs. Used by Billboard and Kazališta.

<div data-tabs>
  <button data-tab="hot100" class="is-active">Pjesme</button>
  <button data-tab="b200">Albumi</button>
  <ol data-panel="hot100">…</ol>
  <ol data-panel="b200" hidden>…</ol>
</div>

Folding days

Each theatre day is a <details class="theaters__day"> with the day header as its <summary>. Days start folded, so two weeks fit on a screen; the header shows the date and how many shows there are, and a plus or minus shows the state. It works without any script.

Weather icons: .wx

An icon is <i class="wx" style="--wx:url(icons/weather/monochrome/rain.svg)">. The SVG is used as a CSS mask over currentColor, so icons follow the theme. When the press inlines an edition it will turn these into data URIs.

Show pictures

A show with a picture prints <figure class="theaters__poster"><img>. A show without one prints theaters__poster--type with the theatre's initials, so the list keeps its rhythm.

Izvori: data-play

data-play holds the path to matter.js. When the section comes near the screen the script loads it, turns every .chip into a body, and starts the simulation; it pauses when the section leaves the screen. The [data-play-shake] button appears only once physics runs. With reduced motion, or without JavaScript, the chips simply sit in rows.

Images: data-viewer

Add data-viewer to an image to make it open full screen. Optional data-full gives a bigger file and data-caption a caption.

Riječililica

Guess a five-letter word in six tries. Green is the right letter in the right place, gold is a letter that is in the word somewhere else, grey is a letter that is not in the word. Lj, nj and dž count as two letters, so ljudi is l, j, u, d, i.

Where the word comes from

At 05:00 the press draws a random word from rijecililica-odgovori.txt skipping any word used in the last year, and records it with the date. The list has 1,183 words, so there is always plenty left to draw from. Nobody sets it by hand, so the admin can play too.

Why there is no answer endpoint

A check on the server would stop old editions working on their own. Instead the answer is printed into the page, scrambled with the edition's date, and checked in the browser. This keeps honest people honest; it is not meant to stop someone reading the source.

AttributeHolds
data-gameThe scrambled answer, base64.
data-game-dayThe edition date, YYYY-MM-DD. It is the key for unscrambling and for saving the game.
data-game-nThe game number, shown when sharing.
data-game-listPath to the guess list.

The scramble

Fold the digits of the date into a seed, then XOR each byte of the UTF-8 word with a value from the seed and its position.

// Go, in the press
func scramble(word, day string) string {
	seed := 0
	for _, c := range day {
		if c >= '0' && c <= '9' {
			seed = (seed*10 + int(c-'0')) % 251
		}
	}
	b := []byte(word)
	for i := range b {
		b[i] ^= byte((seed + i*73 + 41) & 255)
	}
	return base64.StdEncoding.EncodeToString(b)
}

The page does the same steps in reverse. For 27 October 2026 and oblak the result is DsifXe4=, which is what the sample page carries.

Guesses

The guess list is fetched the first time the reader touches the board. A guess that is not on the list is refused with a shake. If the list cannot be loaded (for example a saved copy opened from disk), any five letters are accepted, so the game is never stuck.

Saved games

Games are kept in localStorage under tisak-rijecililica as {"games": {"2026-10-27": {"g": ["krava","oblak"], "done": 1}}}, where done is 1 for a win and 2 for a loss. Played, win rate, current run and longest run are counted from that. Sharing copies a grid of coloured squares, never the word.

Standalone editions

These rules hold for every printed edition:

  • No requests back to the server. No API calls, no answer checks, no analytics inside the edition.
  • Styles and scripts are inlined, and pictures are saved next to the page (or inlined when small), so a source deleting a picture does not break an old edition.
  • Links point outward to the original articles; the edition carries the headline and summary, not the full text.
  • Everything a section needs is printed into the page: all eight cities' forecasts, and the Riječililica guess list (about 100 KB, in a <script type="text/plain" data-game-words>), so the game still refuses made-up words when opened from disk.
  • Optional parts fail quietly: without JavaScript the tabs show their first panel, the days stay open, the game says it needs JavaScript and Izvori shows its rows.

Checking it

The press writes each edition to data/editions/2026/10/27/v1/: index.html, sve.html and images/. It writes into a temporary folder and renames it when complete, so a half-written edition is never served. Copy that folder anywhere and open index.html from disk: fonts, pictures and the link to Sve iz dana all work with no network. samples/edition-2026-10-27-v2/ is a real one to try.

For the static design, tools/pack.py does by hand what the press does: it inlines the stylesheets, scripts, fonts, icons and local pictures into one file.

python3 tools/pack.py design/index.html design/standalone.html

Opened from disk with no other files beside it, that file has no errors: fonts and icons load, the city picker works, the game refuses made-up words, and Izvori runs. Without inlining, a browser blocks fonts, mask icons and the word list on file://, which is why the design folder itself must be served over HTTP.

Pictures: saved first, printed after

The 04:30 fetch downloads the pictures a print can use (only for categories with a lead picture, and only for the few newest items of each source), shrinks them to at most 1000 px wide and keeps them in a picture store named by their contents, so the same picture on ten days is stored once. Photos are saved as JPEG at quality 78, pictures with transparency as PNG, and SVG logos as they are. WebP was the plan, but Go cannot write WebP without C code, and JPEG at this size is close enough. The 05:00 press never touches the network: it takes pictures only from the store and links them into the edition's images/ folder (hard links, so they cost no extra disk). A picture that failed to download prints as the lettered card instead.

Sources

Sources belong to categories, and every source is listed in the dashboard with its logo, so a new fetcher only needs a row and a small Go type. News fetchers read RSS or a page and give items; data fetchers (weather, films, charts, theatres, sport fixtures) give structured rows for their own section.

Adding a source Stage 2

Until the dashboard exists, an RSS source is a line in cmd/tisak/seed.go (name, kind, URL, logo, share per edition, and a time zone for feeds that write local time but label it GMT, as Germanijak does). The seed only runs on an empty database, so on a running one add the row with SQL. The plan once the dashboard exists:

  1. Save a sample of the feed or page in research/samples/ (add a line to fetch-samples.sh).
  2. If it is RSS or Atom, no code is needed: in the dashboard, open Sources, add the URL, pick its category and upload its logo.
  3. If it is anything else, write a fetcher: a Go type with a name and a Fetch method, plus a test that reads the saved sample. Register it, and it shows up in the Sources list.
  4. Run tisak -fetch-now, check the items on the Today page, and the next print picks them up.

Access and paper

  • Tabs use role="tab" and aria-selected; the game board announces each row (for example "krava: drugdje, nema, drugdje, nema, nema") and its message line is a live region.
  • The physics and the poster wall respect prefers-reduced-motion.
  • Printing on paper hides the game, Izvori and the settings panel, and keeps text black on white.
  • Layouts are checked at 1440 and 390 pixels wide with no sideways scrolling.
